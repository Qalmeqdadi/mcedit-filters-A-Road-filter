# Radiant Marina Sale Desk

A buyer-acquisition and market-intelligence system for selling one 3-bedroom off-plan apartment in
Radiant Marina Towers, Al Reem Island, Abu Dhabi, by 30 September 2027.

Self-contained: Python 3 standard library and plain HTML/JS, with **no dependencies to install**. It is
independent of the Next.js app in the repository root.

| File | What it is |
|---|---|
| [`RESEARCH.md`](RESEARCH.md) | **Start here.** Source-linked buyer/broker research, broker shortlist, comparables, price estimate, net proceeds, fees, risks |
| `public/` + `server.py` | The dashboard (local web app) |
| `scripts/refresh.py` | On-demand refresh: Property Finder listings, project page, agent profiles → flags and re-scored leads |
| [`RESEARCH_PROMPT.md`](RESEARCH_PROMPT.md) | The assisted research workflow for sources that can't be automated (social platforms, Arabic classifieds) |
| `marketing/` | Adverts in English and Arabic, Facebook posts, WhatsApp and LinkedIn messages, investor fact sheet, 60-day plan. **All drafts, nothing published.** |
| `data/` | All data as JSON (see below) |

## Run the dashboard

```bash
cd radiant-marina
python3 server.py            # then open http://127.0.0.1:8787
```

Tabs: Overview · Lead pipeline · Broker & investor DB · Comparables · Pricing analysis · Lead scoring ·
Campaigns & outreach · Approvals · Timeline · Proceeds calculator · Research refresh.

Your working state (lead statuses, notes, approvals, outreach log, calculator inputs, campaign ticks) is
saved to `data/state.json`, which git ignores, so it stays on your machine. Delete that file to start again
from `data/state.seed.json`.

**The contact approval workflow.** Open a lead → *Draft message* (English or Arabic template, filled in) →
it waits in **Approvals** → you edit and **Approve** → you send it yourself from your own WhatsApp,
LinkedIn or email → **Mark as sent**, which logs it and moves the lead to *Contacted*. Contact stages in
the pipeline stay locked until a message for that lead is approved. The software never sends anything.

## Refresh the data

```bash
python3 scripts/refresh.py          # about 2 minutes, about 35 requests to propertyfinder.ae
```

Or use **Run refresh now** in the dashboard. It needs outbound HTTPS to `www.propertyfinder.ae`. No
recurring schedule is configured; see `RESEARCH_PROMPT.md` if you want one.

## A shareable snapshot

```bash
python3 scripts/build_static.py     # writes dist/dashboard.html: one file, data included
```

The snapshot works offline. Edits in it are kept in that browser only.

## Data files

| File | Content | Provenance |
|---|---|---|
| `property.json` | Your unit and targets | **You**: verify against the SPA and the Radiant statement |
| `comparables.json` | Radiant Marina listings, Reem 3BR listings, project facts | Property Finder, auto-refreshed (asking prices) |
| `claimed_transactions.json` | Reem sales claimed by agents on their profiles | Property Finder agent profiles: self-reported, **not registry-verified** |
| `agents.json` | Licence, languages and track record of agents holding 2BR/3BR stock in the towers | Property Finder |
| `leads.json` | `auto` = broker leads generated by the refresh; `manual` = verified leads you or Claude add; `rejected_candidates` | Mixed, each row carries its source and confidence |
| `market.json` | Market facts, resale rules, unverified snippet comparables, investor channels, buyer-intent search log, capability notes | Web search, every item with a URL |
| `refresh_log.json` | The last 50 refresh runs and their flags | Generated |

## Ground rules built in

- Leads are never manufactured. The *Add a lead* form requires a source URL, the poster's words and a date.
- Asking prices, agent-claimed sales and registry transactions are always labelled separately.
- Bayut and Dubizzle bot protection is not bypassed, and Property Finder is read only on robots.txt-allowed paths.
- No message is sent and no advert is published by the software.
