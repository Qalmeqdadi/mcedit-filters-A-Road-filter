## Differences from the process document

| Ref | Change | Why |
| --- | --- | --- |
| 1.5 | Shipper prepares and uploads the full document pack with the request. | The shipper already holds these papers. Reading them at intake removes re-keying and lets 6.2 validate instead of collect. |
| 4.4.8 | Feasibility also checks that the document pack fits the cargo. | With documents collected up front, a missing DG declaration can kill an option before the shipper sees it. |
| 4.7 | Options are published straight to the shipper workspace at an all-in price (carrier cost plus desk margin applied by rule). The desk approves only exceptions. | Removes the forwarder relay (carrier → desk → shipper) without exposing carrier cost or desk margin to the shipper. |
| 4.8.2 | Internal approval happens before publication, not after acceptance. | In the direct flow the shipper accepts a binding price, so the desk must approve exceptions before the shipper can see the quote. |
| 4.8.1 | Shipper acceptance hands the accepted option and the full document pack to the desk for booking (5.1). | The forwarder steps back in for execution only: booking, filing, pickup and handover. |
| 4.1.2 | Carriers receive a redacted pack (no party names, no cargo value) until a booking is confirmed. | The commercial invoice names the shipper; sending it with the RFQ would let carriers bypass the desk. |
| request | Added awaiting_info and cancelled. | 1.1.5 tracks the wait for missing data; requests can be withdrawn. |
| quote | Added pending_approval. | 4.8.2 internal approval needs a state the shipper cannot see. |
| shipment | Added cancelled. | A planned shipment can be cancelled before it moves. |
| charge | Added written_off; invoiced can settle without a dispute; expected can be invoiced directly. | 8.5.4 write-offs; most charges are never disputed. |
| bid | New machine: invited → chased → replied → superseded, or declined / no_reply. | 4.1.5 chasing and 4.2.3 revisions need explicit states. |
| document | New machine: requested → uploaded → extracted → validated or rejected. | 1.5 and 6.2 need to know where each document stands. |
| capacity_hold | New machine: held → converted, released or expired. | 2.4.1 and 2.4.2 soft holds against live quotes. |
